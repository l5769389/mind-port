# Limitations

MindPort v1 targets useful rendering and integration, not pixel-level reproduction of XMind or ProcessOn.

## Rendering Fidelity

Official editors have private layout engines, theme inheritance rules, and shape libraries. MindPort keeps the output readable and structured, but some spacing, routing, gradients, shadows, icons, and editor-specific decorations will differ.

For XMind, use `compatibilityMode: "preview"` or `renderMode: "thumbnail"` when the embedded thumbnail is the best available visual reference.

For ProcessOn diagrams, MindPort preserves geometry and major style fields. It does not attempt to re-route complex curves exactly like ProcessOn.

For ProcessOn mind maps, MindPort reads common `structure` and `theme` fields and provides manual layout/style overrides. Official canvas thumbnails, decorative template thumbnails, exact branch routing, and every editor-side style variant are still approximations.

## Unsupported Or Degraded Fields

Common degradations include:

- Gradients rendered as solid fills.
- Unknown marker icons rendered as compact text markers.
- Unknown ProcessOn shapes rendered as rectangles or unknown fallbacks.
- Complex curves rendered as straight or polyline connectors.
- Missing image resources rendered as text/image placeholders.
- Editor-only metadata kept in `raw` fields but not visually rendered.

## Security

The viewer helper sets SVG using DOM insertion. Only pass SVG generated by MindPort or otherwise trusted/sanitized SVG.

Runtime parsing and rendering do not fetch network resources. External preview URLs belong in benchmark tooling or user code that explicitly opts into loading them.

## ProcessOn Samples

Public ProcessOn pages often expose preview images, not exportable `.pos` data. Real POS coverage depends on local exports or user-provided fixtures. The package supports the common JSON wrappers seen in POS exports and keeps unknown raw fields for future compatibility work.
